# battle_protocol

[![style: very good analysis][very_good_analysis_badge]][very_good_analysis_link]
[![License: MIT][license_badge]][license_link]

The **commands, events, battle-log format, host–client messages and API key format** of Battle Team, a 3D,
massive, persistent, real-time team battle game. The simulation host, the client and the
Appwrite Functions share them (stack decisions 2, 3, 6 and 7 of the plan).

- **Commands** (Command pattern): an `Order` (sealed: moves, shots, weapons, flight,
  transports, role actions, captures and pushes, storage, purchases, transfers, tree
  nodes, prisoner offers, the HQ and its manager) with its sender (account, section), the
  sender's time, and the origin (player, AI or server) and sequence number the host
  stamps on it.
- **Events**: the sealed `BattleEvent`s the host produces. An attack's outcome (hit or
  miss, damage, kill, prisoner, defection, by target type) is one event, in the same log
  entry as the attack, so statistics need no replay.
- **The battle log**: `LogEntry`s, each a battle time, the accepted command if any, and
  its events.
- **Messages over the socket**: from a client, `SignIn` (a JWT or an API key),
  `SendCommand` (a command with the client's request ID), `ResyncRequest`, `Heartbeat`;
  from the host, `SignInAccepted` or `SignInRefused`, `CommandAccepted` or
  `CommandRefused`, a section's whole `SectionView` (its units and private state, HQs,
  relics, victory countdown, delta layer), each tick's `TickUpdate` (positions of
  moving units, units in and out of sight, events, grouped bursts, unseen hits, changed
  private state), `RelicAlert` and `Goodbye`.
- **API keys**: `btk_` and 256 random bits, generated by the server, shown once, stored
  as their SHA-256.
- **Pure Dart, no I/O in `lib/`**: the caller passes bytes, text and a secure random.

## The format (version 1)

A data contract, versioned from the start. Every message lists its fields once
(`lib/src/codec/wire.dart`), and two encodings write them:

| | Binary (`BinaryProtocolCodec`) | JSON (`JsonProtocolCodec`) |
|---|---|---|
| Used for | the battle log and the socket | HTTPS calls (AI agents, the server) |
| Version | a varint first | `"v": 1` |
| Integers | zigzag LEB128 varints, from −2^52 to 2^52 − 1 | numbers |
| Doubles | little-endian IEEE 754, exact | numbers |
| Times | microseconds, as integers | `*_us` fields, microseconds |
| Positions | centimetres, 3 integers | `[x, y, z]` in metres |
| Directions | millionths, 3 integers | `[x, y, z]` |
| Cells | `x`, `y`, optional island | `[x, y]` or `[x, y, "island"]` |
| Enums, types | their index | their snake-case name |
| Optional fields | a byte 0 or 1, then the value | left out (or `null`) |

A battle log file is `BTLG`, the version, then one frame per entry (its length, then the
entry), so the host can append entries one at a time. Decoders accept only version 1 and
throw a `ProtocolException`, and nothing else, for any other input: unknown types and
fields, values of the wrong kind, truncated input, lengths beyond the input.

**Frozen samples.** `test/fixtures/v1/` holds the binary (`.hex`) and JSON encodings of
one sample of every command, event and log entry (`test/helpers/samples.dart`), and a
whole log. The tests fail when an encoding no longer matches them. A new order or event
gets a new tag at the end of its list and a sample; add its encodings with
`dart run tool/write_samples.dart`, which never changes a committed sample. Any other
change to the format is a new version.

## Part of hawkbee

This repository is a git submodule of the
[hawkbee](https://github.com/hawkbee1/hawkbee) monorepo and **only builds inside
it** (pub workspace, `resolution: workspace`):

```sh
git clone --recurse-submodules https://github.com/hawkbee1/hawkbee.git
cd hawkbee && flutter pub get
```
